# Nightingale 工程化 Agent 升级：全局审查与方案

**目标：** 把 Nightingale 从 72 小时原型升级为可直接交付的临床 Agent 产品。Agent 是主线，前端、认证、权限、安全同步提升到工程交付水平。
**本次窗口：** 审查、方案与全部编码，不调用付费 API。
**下一窗口：** 真实 API 测试（见 §8）。

> 范围调整：之前路线中的"项目 1：手写 Agent 循环"不属于本项目。手写循环已整体删除，Agent 统一运行在 Anthropic SDK 的 Tool Runner（`client.beta.messages.toolRunner`）上。项目代码只负责业务部分：工具、权限委托、确定性护栏、持久化和评测。

## 1. 全局审查结论

按严重度排序。P0 = 交付前必须修复，P1 = 工程化必备，P2 = 体验与可维护性。

### 1.1 安全与认证

| 级别 | 问题 | 证据 | 处理 |
| --- | --- | --- | --- |
| P0 | `/api/demo` 无需登录，GET 请求会写库（upsert 诊所与员工），并返回全部患者姓名与电话 | `src/lib/api/handlers.ts` `handleDemoBootstrap` | 删除该端点；患者列表改为登录后、按诊所隔离的 `/api/patients` |
| P0 | 患者用"姓名 + 电话 + 生日"登录，都是公开或可推测信息；员工"二次验证"等于工号本身 | `src/lib/auth/login.ts` | 改为邮箱 + 密码（scrypt 加盐哈希），删除基于知识的登录 |
| P0 | 数据库无真实密码（`dev-only-not-a-real-hash`），无注册、激活、停用、锁定流程 | `prisma/seed.ts` | 建立完整账号生命周期：注册、邀请激活、停用、锁定、改密 |
| P0 | 登录弹窗预填演示凭据 | `LoginModal.tsx` | 仅在 `NIGHTINGALE_DEMO_MODE=true` 时显示演示账号入口 |
| P1 | 会话无法吊销：改密、停用后旧 Cookie 仍有效；UI 没有退出登录 | `session-token.ts` | 令牌携带 `sessionVersion`，改密、停用或"退出所有设备"时递增 |
| P1 | 写请求仅靠 SameSite 防 CSRF | `requireActor` | 非 GET 请求校验 `Origin` / `Referer` 与 Host 一致 |
| P1 | 无登录限流与失败锁定 | — | 按 IP + 账号限流；连续 5 次失败锁定 15 分钟；错误信息不区分"账号不存在"与"密码错误" |
| P1 | 无安全响应头（CSP、frame-ancestors、nosniff、HSTS） | `next.config.ts` | 全站统一下发 |
| P1 | 页面无路由保护，未登录直接渲染应用壳 | `app/page.tsx` | `middleware.ts` 跳转登录页；所有 API 继续在服务端鉴权 |
| P1 | 开发环境仍接受裸 `x-user-id` 请求头 | `session.ts` | 仅在测试环境显式开启 |
| P2 | 登录成功 / 失败无审计 | `AuditLog` | 记录登录事件，元数据不含 PHI |

### 1.2 权限（RBAC）

- 服务端权限矩阵（`rbac.ts`）设计合理，**但只覆盖了笔记读写**，没有覆盖账号管理、患者建档、Agent 结果可见性。需要补齐：管理员管理账号；员工与医生建档患者；风险等级对员工可见，但引用了医生草稿的依据条目对员工隐藏。
- 自动触发的 Agent 不能"借用"写笔记那个人的权限，否则结果会因触发者不同而变化。改为每个诊所一个**服务账号**（不可登录），以医生可见范围读取，展示时再按查看者的权限过滤。

### 1.3 前端与交互

| 级别 | 问题 | 处理 |
| --- | --- | --- |
| P1 | 顶栏是演示用的角色切换器，患者下拉框直接展示电话号码 | 正式的用户菜单（姓名、角色、账号、退出）；患者选择器不显示电话 |
| P1 | 没有工作入口：医护登录后看不到"今天该先看谁" | 新增 `/patients` 工作列表，按 Agent 风险等级与复核时限排序 |
| P1 | 没有登录、注册、激活、账号、管理页面 | 新增对应页面 |
| P2 | 加载、错误、空状态各写各的；弹窗无焦点管理；没有操作反馈 | 统一的状态组件；表单可访问性（label、aria-live、键盘操作） |
| P2 | `TimelineView` 554 行，数据获取与展示混在一起 | 新页面按"数据钩子 + 展示组件"拆分；旧组件本次不重写 |

### 1.4 Agent 层（上一轮交付后的状态）

- 交班摘要 Agent 的权限边界、引用校验和危急下限设计成立，评测框架完整。
- 问题一：运行在手写循环上，维护成本高，且不在本项目范围内。改用 SDK Tool Runner。
- 问题二：只有"按需生成"一种 Agent，没有**自动**工作的 Agent。临床最需要的"自动判断风险等级"缺失。
- 问题三：工具抛出的异常会被 Runner 原样回填给模型（实验确认 `Error: <内部信息>`）。需要在工具层统一包装成安全信息。

## 2. Agent 应用全景

| 编号 | Agent | 触发方式 | 产出 | 人在回路 | 本次状态 |
| --- | --- | --- | --- | --- | --- |
| A1 | **风险分级 Agent** | **自动**：笔记新建 / 修改 / 回滚后入队；也可手动重评 | 患者级风险等级（危急 / 高 / 中 / 低）、复核时限、驱动因素（每条带原文引用）、置信度 | 医生可覆盖等级（必填理由、审计）；覆盖持续到下一份新笔记 | ✅ 实现 |
| A2 | 交班摘要 Agent | 手动 | 逐条带引用的交班摘要 + 随访提议 | 提议需医生接受才写入 | ✅ 迁移到 SDK Runner |
| A3 | 患者版小结起草 | 医生在"发布最终小结"前手动触发 | 通俗语言的患者版小结草稿 | 医生编辑并发布；不发布不可见 | 📋 下一阶段 |
| A4 | 待办抽取 | 笔记保存后自动 | 从笔记里抽取"已安排但未完成"的事项，形成随访提议 | 同 A2 的提议流程 | 📋 下一阶段（复用 A2 的提议与去重） |
| A5 | 病历问答 | 手动提问 | 带引用的回答，查不到就明确说"病历未记录" | 只读 | 📋 下一阶段（复用 A2 的工具与引用校验） |
| A6 | 高亮召回补充 | 笔记保存后自动 | 规则引擎漏掉的风险短语，以"建议高亮"形式出现 | 医护确认后才成为正式高亮 | 📋 下一阶段 |

A1、A2 先做，原因：A1 直接回答"谁需要先看"，是工作列表的排序依据；A2 已经有完整评测，迁移后能继续用同一套评测做回归。A3–A6 共享同一平台层（§3），后续每个只需新增工具、输出 schema、护栏和评测用例。

## 3. Agent 平台层

```
路由处理器（鉴权、限流）──┬─ 同步：交班摘要、手动重评
                         └─ 异步：after() → 风险作业队列（数据库表）→ 处理器
                                        │
                     runToolAgent()  src/lib/agent/core/run-agent.ts
                       ├─ client.beta.messages.toolRunner（SDK 负责循环与重试）
                       ├─ thread: false（不使用服务端会话保存，适配 PHI）
                       ├─ 每轮观察：用量、stop_reason、实际服务模型、回退
                       ├─ 终止工具：模型单独调用 submit_* 时停止，输入用 zod 校验
                       ├─ 预算：最大轮数、累计 token、总超时（AbortSignal）
                       └─ 工具：defineTool() = zod schema → 严格模式 JSON Schema
                                + 安全错误包装 + 耗时 / 大小记录
                     ↓
                 确定性护栏（引用校验、否定冲突、危急下限、注入拦截、脱敏）
                     ↓
                 AgentRun（状态、用量、元数据轨迹）+ 各 Agent 的结果表 + AuditLog
```

| 关注点 | 设计 |
| --- | --- |
| 权限 | 工具绑定"一个执行者 + 一个患者"，没有 `patient_id` 参数。人工触发时以当前用户身份读取；自动触发时以诊所服务账号（医生可见范围）读取，展示时再按查看者过滤 |
| 成本 | 每次运行有 token 预算和轮数上限；按用户限流；风险作业按患者去重，输入没变就不重跑（基于笔记版本、高亮和待办状态的哈希） |
| 可用性 | 未配置 API key 时：风险分级降级为纯规则结果并明确标注；交班摘要返回 503 并给出说明 |
| 开关 | `NIGHTINGALE_AGENTS_ENABLED=false` 一键关闭所有模型调用（规则结果照常工作） |
| 可观测 | `AgentRun` 记录每次运行的模型、提示词哈希、轮数、token、耗时、结果类别；轨迹只存元数据，不存原文 |
| 版本 | 提示词带版本号和内容哈希，评测结果绑定哈希 |
| 评测 | 每个 Agent 一套用例、评分器和统计报告；离线基线进 CI，真实模型按需付费运行 |

## 4. 风险分级 Agent（A1）详细设计

**等级定义**

| 等级 | 含义 | 复核时限 |
| --- | --- | --- |
| CRITICAL | 当前存在危及生命的表现或严重异常生命体征 | 立即 |
| HIGH | 当前红旗症状或需当班处理的显著异常 | 4 小时内 |
| MEDIUM | 活动性问题、待结果的检查、需跟进的症状 | 24 小时内 |
| LOW | 稳定、常规随访 | 常规 |

**确定性下限**：只升不降，代码执行，不靠提示词。只看"最近一次就诊前后 7 天内"的笔记，避免陈旧发现永久抬高等级。

| 来源 | 下限 |
| --- | --- |
| 严重生命体征（SpO2 < 90%、BP > 180/110），且处于肯定语境 | CRITICAL |
| 规则引擎的危急词（胸痛、气短、过敏性休克、超高热、严重呼吸窘迫），且处于肯定语境 | HIGH |
| 医护人工标记的危急高亮 | HIGH |
| 发热（肯定语境） | MEDIUM |

最终等级 = max(模型等级, 下限)。被下限抬高时，界面显示"由安全规则从 X 上调"及触发它的原文。

其他设计：
- **模型输出校验：** 每条驱动因素必须引用原文，引用不成立就删除。"抬高风险"的因素若与自身引文的否定相矛盾，也删除。复核时限不能宽于等级对应的时限，宽了自动收紧。
- **降级运行：** 无 API key、Agent 被关闭或模型调用失败时，等级 = 下限（没有下限就是 LOW），标注"规则评估"，不会因为模型故障而没有等级。
- **人工覆盖：** 仅医生和管理员可以覆盖，理由必填，写审计日志。工作列表显示覆盖后的等级，并标出"已人工覆盖"。
- **可见性：** 等级对员工和医生可见，对患者不可见。引用了员工无权查看的笔记的依据条目，对员工隐藏，并显示"1 条依据来自受限笔记"。

## 5. 认证与权限方案

- **账号：** 邮箱 + 密码，scrypt 加盐哈希（N = 2^15）。状态分为 ACTIVE / INVITED / DISABLED。服务账号不可登录。
- **注册：**
  - 患者自助注册：需要诊所提供的注册码。
  - 员工和医生：只能由管理员邀请，通过一次性激活链接（令牌只存哈希，72 小时有效）设置密码。
  - 员工和医生可以为患者建档，并可选生成患者门户激活链接。
- **会话：** HMAC 签名的 HttpOnly Cookie，8 小时有效，携带 `sessionVersion`。改密、停用或"退出所有设备"会让旧会话立即失效。
- **防护：**
  - 登录：按 IP 和账号限流；连续失败锁定；用统一的错误信息，并对不存在的账号也做一次哈希计算，防止通过响应时间探测账号是否存在。
  - 写请求校验 Origin。
  - 安全响应头：CSP、frame-ancestors 'none'、nosniff、Referrer-Policy、Permissions-Policy，生产环境加 HSTS。
- **权限矩阵：** 在原有笔记权限之上补充：账号管理（ADMIN）、患者建档（STAFF / CLINICIAN / ADMIN）、风险覆盖（CLINICIAN / ADMIN）、Agent 结果可见性（见 §4）。

## 6. 前端方案

- **应用壳：** 用 `/api/auth/me` 判断登录状态。顶栏包括品牌、诊所、患者选择器（仅医护可见）、语言、用户菜单。导航按角色显示。
- **新页面：**
  - `/login`、`/register`、`/activate`、`/account`（改密、退出所有设备）
  - `/admin/users`（邀请、停用、重发激活链接）
  - `/patients`：工作列表，按风险等级 → 复核时限 → 最近就诊排序，含"新建患者"
- **Glance 页：** 新增风险面板，包括等级、复核时限、驱动因素及引用、下限原因、评估方式（模型或规则）、评估时间与是否过期、重评按钮、医生覆盖表单。
- **统一体验：** 加载、错误、空状态组件；`aria-live` 状态播报；表单 label 关联；手机宽度无横向溢出；新增文案覆盖五种语言。
