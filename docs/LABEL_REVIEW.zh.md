# 评测标签独立审核流程

**目的：** 目前所有金标准（风险等级、交班必含事实、不得断言项、随访期望）都由项目作者根据笔记文本标注，没有临床专业人员核实。这是评测结论最大的效度限制（见 [EVALUATION.md](./EVALUATION.md)）。本流程让一位或多位临床人员在不看作者标签的情况下独立标注，计算一致性，并按规则处理分歧。

## 1. 数据集划分（先于审核固定）

| 集合 | 内容 | 规则 |
| --- | --- | --- |
| 核心集 | 交班 20 例（seeded 10 + adversarial 10）；风险 28 例（含 7 例 holdout） | **冻结。** hash 固定在 `tests/test_case_sets.test.ts`，任何修改都会让测试失败。所有已发布的数字都对应这一集合 |
| 挑战集 | 交班 `evals/cases/challenge.ts`；风险 `RISK_CHALLENGE_CASES` | **持续扩充。** 新的难点和每一次观察到的失败都加在这里，单独报告，不改变核心集的数字 |

这样可以避免"测试集被不断修改得越来越符合模型表现"：核心集不随模型变化；挑战集只增不改，并且分开报告。

单位是病例而不是重复运行：所有置信区间都按病例做聚类 bootstrap，同一病例的多次运行不被当作独立样本。

## 2. 导出（盲审）

```bash
npm run eval:export-labels
```

在 `evals/results/label-review/` 下生成两个文件：

- `risk-labels.csv`：每个风险病例一行，包含笔记全文。审核者填写 `reviewer_level`（LOW / MEDIUM / HIGH / CRITICAL）和 `reviewer_comment`。
- `handover-labels.csv`：每条交班期望一行（必含、不得断言、随访）。审核者填写 `reviewer_agrees`（Y/N）和 `reviewer_comment`。

默认**不包含**作者标签。等级定义请提供 [AGENT_DESIGN.md](./AGENT_DESIGN.md) §2.4 与风险提示词中的等级说明，但不要提供作者的理由。

## 3. 计算一致性

```bash
npm run eval:label-agreement -- evals/results/label-review/risk-labels.csv evals/results/label-review/handover-labels.csv
```

报告内容：

- **风险：** 完全一致率、相差一级内一致率、二次加权 Kappa、混淆矩阵（行为审核者，列为作者），以及全部分歧病例。
- **交班：** 审核者同意的期望所占比例，以及全部不同意的条目。

建议的解读门槛（工程目标，不是行业标准）：Kappa ≥ 0.8 视为标签可信；0.6–0.8 需要逐条仲裁；低于 0.6 说明等级定义本身需要修改。

## 4. 处理分歧

1. 用 `npm run eval:export-labels -- --with-gold` 导出带作者标签的版本，与审核者逐条讨论。有两位以上审核者时，以多数意见为准。
2. **作者标签确有错误：**
   - **核心集：** 在单独的提交中修改，同时更新测试中的 hash，并在提交说明里写明哪些已发布结果因此失效，需要重跑。
   - **挑战集：** 直接修改。
3. **等级定义有歧义**（例如新发劳力性胸痛算 HIGH 还是 MEDIUM）：把"相差一级内一致率"和 Kappa 作为主要指标，并把这种病例记录为"本地政策相关"。
4. 审核结果（CSV 与一致性输出）存档到 `docs/eval/`，注明审核者资历与日期。不要写入个人身份信息。

## 5. 规模目标

| 集合 | 现在 | 下一阶段目标 |
| --- | ---: | ---: |
| 交班（核心 + 挑战） | 20 + 10 | 50–100 |
| 风险（核心 + 挑战） | 28 + 8 | 60–100，各等级与语境均衡 |

扩充时优先补充：
- 失败病例（每次评测中出现的新失败模式，都转为挑战集用例）；
- 临床审核者提出的真实场景（去标识化后）；
- 低频高危的表现。
